## 5. 失败模式分析（Failure Mode Analysis）

> 本节刻意区分“整体 mAP”与“盲道监测任务真正关心的问题”。

### 5.1 blind_road（主任务，安全相关）

| 统计 | 数值 |
|---|---|
| 测试集 blind_road mAP50 | 0.8486 |
| blind_road Recall | 0.8024（约 20% 实例漏检） |
| **含 blind_road 漏检的图像数** | **104 / 4163（2.5%）** |
| 盲道漏检实例数（per_class_missed） | 803 |
| 含 blind_road 误检的图像数 | 63 / 4163（1.5%） |
| 盲道误检实例数 | 74 |

**回答约束中 6 个关键问题：**

1. **blind_road 是否容易漏检？** — 在 2.5% 的测试图上至少漏掉一段盲道；实例级召回 0.80。整体不算“容易漏检”，但**约 1/5 的盲道实例未被检出**，对安全系统而言是必须正视的缺口。
2. **哪些场景最容易漏？** — 对照图显示：远距离小段盲道、被车辆/行人遮挡的盲道、强阴影或反光低对比地面、复杂背景中的磨损盲道。
3. **哪些障碍物最容易漏？** — 与盲道相邻、体积小的障碍物（如 plant_pot R=0.55、guard_rail R=0.68）检测偏弱；但这些类实例级漏检更多源于“类本身难”，而非“盲道判定失败”。
4. **哪些类别最容易混淆？** — 红/绿灯区分良好（green 0.95 / red 0.88，未混淆）；manhole 0.87 良好。主要混淆来自 **pole ↔ guard_rail ↔ tree**（均为竖直线状目标）以及 **person/pole/tree 的背景误检**。
5. **小目标是否明显影响结果？** — 是。Recall 偏低的类（truck/bus/bicycle/dog）多为远处小目标或稀有目标，小目标漏检是整体 Recall 0.70 的主要拖累。
6. **是否已适合进入实时摄像头测试？** — **适合**（见第 7 节 Go/No-Go），但需对 blind_road 采取“低置信阈值 + 告警降级”策略，避免漏检直接转化为危险。

### 5.2 长尾类别

表现最弱（mAP50 升序）：**truck 0.538（R=0.447，最差）→ bus 0.610（R=0.484）→ bicycle 0.652（R=0.532）→ dog 0.670 → plant_pot 0.702（R=0.548）→ guard_rail 0.703**。这些类与训练集 437:1 长尾分布一致，是**数据不均衡导致的召回不足**，非标签错误。

### 5.3 整体漏检/误检规模

- 任意类漏检图像：**2482 / 4163（60%）** — 26 类检测中，多数图至少漏掉一个类，属该规模模型的正常水平，非系统性崩溃。
- 任意类误检图像：**2438 / 4163（59%）** — 同样属正常水平。

### ⭐ 结论：**GO（进入 Phase 17 摄像头实时检测）**

**但附条件建议**（非阻断）：
- 实时阶段对 `blind_road` 采用**更低置信阈值（如 0.15–0.20）**并配合告警，以压低 20% 的实例漏检。
- 长尾弱类（truck/bus/bicycle/plant_pot/guard_rail）在实时告警中**暂不作为高可信事件**，避免误报干扰。
- 建议 Phase 17 先做“轻量摄像头冒烟”（能实时出框 + 延迟达标），再做完整产品。
